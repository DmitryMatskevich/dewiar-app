# Скил: аудио и видео — транскрибация и обработка

## 0. Полный текст ролика — инструмент `transcribe`

Кнопка «Транскрибировать» в верхней строке виджета и разделе «Задачи» открывает очередь: ссылки, несколько файлов с диска и уже выбранные вложения. Запуск выполняет весь процесс до исходных TXT/SRT и чистового Markdown одной задачей. Если источников несколько, пользователь видит число элементов и запускает пакет. Не предлагай отдельную повторную загрузку после нажатия этой кнопки.

Готовые результаты и скачанный звук используются между задачами. Повтор того же завершённого запроса открывает существующую задачу. При частичной ошибке пакет можно повторить: успешные элементы берутся из кэша, а сохранённый звук не скачивается заново. Разные YouTube-ссылки на один ID считаются одним источником. Изменённый локальный файл обрабатывается заново.

Явная просьба «давай сделаем транскрибацию» со ссылкой в чате автоматически создаёт обычную фоновую задачу обработки, без обращения к модели для запуска. Её пульсирующая кнопка находится в первой строке виджета: нажатие открывает именно эту задачу. В карточке и журнале показываются текущий этап и обработанное время записи. Нельзя сообщать о запуске, если в списке задач нет созданной задачи. Одна ссылка без пояснения требует выбора: открыть ролик или извлечь текст. Просьба открыть ролик не является разрешением на транскрибацию.

Фразы «Извлеки текст», «Извлеки голос», «Транскрибируй», «Расшифруй видео» и «Обработай список роликов» с видео, аудио или ссылкой запускают один процесс: получить текст речи инструментом `transcribe`. Пользователю не нужно произносить слово «транскрибируй». Если источник ещё не указан и его нет во вложениях или контексте, попроси ссылку или файл. «Извлеки голос» в этом контексте означает текст произнесённых слов; явную просьбу сохранить звуковую дорожку в MP3/WAV выполняй как извлечение аудио (раздел 1).

Передавай источник сразу в `transcribe`. По ссылке не скачивай страницу YouTube как видео через `download` и не ограничивайся текстом `read_webpage`: он может содержать лишь отрывки.

```json
{"path":"https://www.youtube.com/watch?v=zFHJvXrzuvg"}
```

Локальный файл:
```json
{"path":"uploads/встреча.mp4","language":"ru"}
```

Пакет (один вызов, последовательная обработка):
```json
{"urls":["https://youtu.be/first","https://youtu.be/second"],"language":"ru"}
```

Список из файла в папке задачи — по одной ссылке на строку; пустые строки и `#` пропускаются:
```json
{"urls_file":"urls.txt","language":"ru"}
```

- По ссылке сначала извлекаются полные авторские или автоматические субтитры. Если непустого текста нет, инструмент скачивает аудио и распознаёт его. Для русского используется установленная в Dewiar модель GigaAM v3, выбранная в настройках слуха (по умолчанию `gigaam-v3-e2e-rnnt`). Это работает внутри приложения без Codex и его окружений.
- `language` — язык речи для распознавания, по умолчанию `ru`. Готовые субтитры сохраняются с указанием их фактического языка в отчёте. GigaAM не переводит речь и не распознаёт другие языки: для них при отсутствии субтитров используй раздел 2.
- Результат каждого источника — отдельная папка `outputs/transcripts/<id>/`: `transcript.txt` (исходный текст), `transcript-timed.txt` (метки времени), `transcript.srt`, `segments.json` и `metadata.json`. `transcript.clean.md` — связный текст без номеров фрагментов и таймкодов, очищенный по правилам. Затем создаётся `transcript.summary.md` — общее резюме: о чём ролик, кто выступает, основные идеи и заключение/вывод. `cleanup.json` содержит журнал удалений и кандидатов на сверку; `transcript.review.md` — список сомнительных мест со ссылками на аудио. Исходные TXT/SRT, чистовой Markdown и резюме автоматически показываются в «Результатах» задачи. Имена папок уникальны: одноимённые ролики не затирают друг друга.
- `outputs/transcripts/batch-results.json` фиксирует успех или ошибку каждого источника, метод и язык; `errors.log` содержит причину сбоя. Ошибка одного источника не прерывает остальные. Между сетевыми источниками есть пауза; ограничение YouTube не пытайся обходить частыми повторами.
- Повторный вызов использует готовые результаты. `force:true` запускает обработку заново. Статус `error` и пустое распознавание не считай успехом. При остановке задачи частично распознанную речь не выдавай как полный текст.
- Длинные записи GigaAM режет по тихим местам на фразы до 22 секунд. Отдельных спикеров инструмент не определяет; не придумывай разметку говорящих.
- Читай отчёт, затем начало и конец TXT. Не распознавай повторно успешный результат «для проверки». Чистовой Markdown создаётся отдельным этапом автоматически. Не объявляй неоднозначные места проверенными по аудио: они остаются в чистовом тексте и попадают в список сверки. Осмысленные «да», измерения «10 мм», технические слова (например «тампер»), условия и отрицания сохраняются. Точные соседние повторы могут удаляться в тексте с сохранением последнего варианта; похожие по смыслу фразы требуют проверки. Никакие удаления текста не означают монтаж видео.
- Протокол, выжимку и задачи делай после получения полного текста; большой TXT читай частями через `read_file`. Связывай конспект с исходной ссылкой. Для одного фрагмента записи сначала вырежи его ffmpeg (раздел 1).

ffmpeg УЖЕ установлен на компьютере. Файл без расширения? Определи тип по заголовку:
```python
h = open('uploads/файл','rb').read(16).hex()
# 'ftyp' в hex (66747970) → MP4-видео; 'ID3'/'fffb' → MP3; 'RIFF' → WAV
print(h)
```

## 1. Извлечь аудио (весь файл или фрагмент)
СНАЧАЛА создай outputs/: `os.makedirs('outputs', exist_ok=True)` — иначе ffmpeg упадёт «No such file or directory».
```python
import os, subprocess
os.makedirs('outputs', exist_ok=True)
# фрагмент с 17 по 80 сек, моно 16кГц WAV (идеально для распознавания):
r = subprocess.run(['ffmpeg','-y','-i','uploads/video.mp4','-ss','17','-to','80',
                    '-vn','-acodec','pcm_s16le','-ar','16000','-ac','1','audio.wav'],
                   capture_output=True, text=True)
print(r.returncode, r.stderr[-300:] if r.returncode else os.path.getsize('audio.wav'))
```
(Без `-ss`/`-to` — конвертируется весь файл. MP3 на выдачу: `-acodec libmp3lame -q:a 4 out.mp3`.)

## 2. Запасной способ — faster-whisper (другие языки или сервис недоступен)
ВАЖНО: НЕ ставь пакет `openai-whisper` — его установка тянет torch и НЕ УКЛАДЫВАЕТСЯ
в таймаут (проверено: 900с не хватает). Ставь `faster-whisper` — лёгкий и быстрый:
```python
# шаг A: install {"manager":"pip","packages":"faster-whisper"}  (если ещё не стоит)
# шаг B:
from faster_whisper import WhisperModel
model = WhisperModel('small', device='cpu', compute_type='int8')  # 'base' — быстрее, 'small' — точнее
segments, info = model.transcribe('audio.wav', language='ru')      # language=None → автоопределение
parts = [(s.start, s.end, s.text.strip()) for s in segments]
text = ' '.join(p[2] for p in parts)
open('outputs/transcription.txt','w',encoding='utf-8').write(text)
print(text[:1000])
```
Первый запуск скачает модель (~100–500 МБ) — это нормально, дождись. Длинное видео
(>20 мин) транскрибируй кусками по 10 минут, дописывая результат в файл.

```python
# install: {"manager":"pip","packages":"SpeechRecognition pydub"}

```

## 4. Субтитры SRT (из faster-whisper, есть таймкоды в parts)
```python
def ts(t): h=int(t//3600); m=int(t%3600//60); s=t%60; return f"{h:02d}:{m:02d}:{s:06.3f}".replace('.',',')
srt = '\n'.join(f"{i+1}\n{ts(a)} --> {ts(b)}\n{tx}\n" for i,(a,b,tx) in enumerate(parts))
open('outputs/subtitles.srt','w',encoding='utf-8').write(srt)
```

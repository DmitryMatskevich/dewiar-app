# Модели из подписок Codex и Claude Code

В «Модели» появился блок «Модели по подписке». В нём доступны вход, получение списка моделей от официального CLI, выбор модели и (для Codex) уровня рассуждений. «Использовать» сохраняет профиль и делает его активным. «Проверить» в профиле отправляет короткий запрос и расходует лимит плана. Наличие модели в каталоге CLI не гарантирует доступ к ней: окончательную проверку выполняет сервер при запросе.

## Подключение

1. Если включён режим «только локально», рядом с кнопкой «Войти» показано действие «Разрешить внешние подключения». Оно выключает локальный режим для всего Dewiar через существующую настройку безопасности и сразу загружает модели выбранного провайдера. Рядом указано, что приостановленные сетевые функции также смогут возобновиться. Открытие раздела ничего не меняет. Тот же переключатель остаётся в «Безопасность».
2. Codex: «Войти» открывает официальный OAuth-вход в браузере. После завершения входа Dewiar автоматически обновляет состояние и список моделей. Обновление также происходит при возвращении в окно и открытии раздела «Модели». Выберите модель и нажмите «Использовать». Вход Dewiar отделён от настроек рабочего Codex; повторная авторизация нужна один раз.
3. Claude Code: «Войти» открывает официальный CLI в Terminal с командой `/login`. После запуска входа Dewiar раз в три секунды проверяет его завершение и автоматически показывает модели, даже если окно Terminal остаётся открытым. Проверка останавливается после успешного входа, при включении локального режима, закрытии страницы или через десять минут. При истёкшем OAuth-входе нужна повторная авторизация. В любой момент можно обновить карточку вручную.
4. Выберите модель, при необходимости уровень рассуждений, нажмите «Использовать», затем «Проверить» в созданном профиле.

Нужны установленные официальные `codex` и/или `claude`. Dewiar ищет их в PATH, `~/.local/bin`, `/opt/homebrew/bin` и `/usr/local/bin`. Обновления CLI выполняются отдельно. Список моделей соответствует установленному CLI; старый CLI может сообщать устаревшие названия. Полный идентификатор можно также ввести в поле модели профиля.

## Границы интеграции

- Передаётся текстовый контекст Dewiar. Изображения пока отклоняются с понятной ошибкой.
- Встроенные инструменты CLI, пользовательские хуки и MCP не используются. Codex получает временную пустую папку и ограниченную песочницу чтения. Claude Code запускается с пустым набором инструментов, строгой пустой конфигурацией MCP и отключёнными источниками настроек.
- Запросы действий могут возвращаться текстовым протоколом инструментов. Выполнение остаётся в Dewiar, с его ограничениями и подтверждениями.
- API-ключи и альтернативные API-провайдеры из окружения не передаются. Перехода на API при ошибке подписки нет. Условия и лимиты определяет провайдер.
- Пароли и OAuth-токены не попадают в профиль Dewiar. Авторизацией управляет официальный runtime. Отдельный CLI home Codex расположен в `~/.codex/dewiar-subscription`, вне слепков Dewiar. Файлы авторизации из рабочего Codex туда не копируются.
- «Только локально» запрещает запуск транспорта до создания процесса. Включение стоп-крана во время ожидания ответа завершает принадлежащий запросу процесс. Отмена и тайм-аут также закрывают процесс.
- Автоматическая проверка поддержки инструментов при старте не отправляет запрос модели подписки.

- Собранная `.app` прошла полный текстовый ход через настоящее ядро и локальную тестовую модель. Подпись проверена `codesign --verify --deep --strict`.
- Установлены Codex 0.163.0 и Claude Code 2.0.37. Каталоги моделей обоих CLI прочитаны. Отдельный вход Codex Dewiar ещё не завершён. Метаданные Claude сообщили Claude Max, но реальный короткий запрос вернул 401: OAuth access token is invalid. Успешная генерация по подпискам требует входа пользователя и пока не подтверждена.
- На реальном экземпляре приложения проверена блокировка «Обновить модели и вход» при включённом локальном режиме. Текущая модель пользователя `deepseek-r1:70b` и локальный режим сохранены.

Официальные протоколы: [Codex App Server](https://learn.chatgpt.com/docs/app-server), [Claude Code headless](https://code.claude.com/docs/en/headless).


## Разрешение внешних подключений рядом со входом

Кнопка доступна в каждой карточке подписки только при включённом локальном режиме. Изменения в «Безопасность» сразу отражаются на обеих карточках. Если изменение разрешения не удалось, список моделей не запрашивается и ошибка остаётся рядом с кнопкой. Проверка Cocoa/WebKit охватывает оба провайдера, отказ изменения, автоматическое обновление каталога после успеха, синхронизацию карточек и отсутствие скрытого изменения безопасности при открытии страницы.


## Завершение входа Codex и совместимость CLI — 26.10.2026

Исправлена обработка `account/login/completed`: проверяются идентификатор попытки, признак success и состояние аккаунта. Ошибки/тайм-аут не выдаются за успешный вход. Ядро отправляет интерфейсу уведомление; карточка автоматически перечитывает аккаунт и каталог. Возврат из браузера и повторное открытие раздела также обновляют состояние. Вход сам по себе не меняет активную модель: нужно выбрать её и нажать «Использовать».

Живая проверка выявила, что установленный Codex 0.163.0 больше не принимает legacy `readOnly.access`. Адаптер переведён на именованный профиль `dewiar_text` через `permissions` с experimentalApi, без сочетания с sandbox/sandboxPolicy. Профиль разрешает только чтение пустой временной рабочей папки и запрещает сеть локальным командам; встроенные инструменты остаются выключены. Ограничения не ослаблялись. [Официальное описание профилей разрешений](https://learn.chatgpt.com/docs/permissions).

Принят реальный короткий ответ из исходников (4,318 с) и пересобранной .app (4,816 с) через подписку Codex, gpt-6.1-sol, reasoning low. Ни API-ключей, ни пользовательской переписки в этих проверках не использовалось: отправлялась только фиксированная тестовая фраза. На реальном интерфейсе видны «Вход выполнен», каталог из семи моделей и активная кнопка «Использовать». Проверены 16 тестов адаптера, security1019_test, macos_chat_test и Cocoa/WebKit-сценарии успеха/отказа входа и обновления после возврата из браузера. Подпись проверена.


## Вход Claude Code из Terminal — 26.10.2026

Добавлена ограниченная по времени проверка состояния после запуска входа. Она работает для обеих подписок как резервный путь, если Cocoa/WebKit не передал событие возврата фокуса или окно потеряло уведомление ядра. Проверка читает только состояние CLI и каталог моделей, не вызывает генерацию. Локальный режим прекращает проверку. Для Claude вход уже сохранён в официальном CLI; реальный короткий запрос haiku из исходников вернул «Готово.» за 2,226 с. Старый отказ 401 выше больше не описывает текущую авторизацию.

Нативная проверка интерфейса использует подменённый запуск Terminal и ответы CLI: до завершения входа выбор заблокирован, после завершения модели появляются, повторная проверка не запускается, при включении local_only новые запросы не уходят. Пользовательский Terminal и браузер тест не открывает.


## Изоляция настроек Claude CLI

Установленный Claude Code 2.1.308 запускается с `--safe-mode` как для проверки/ответа, так и для входа в Terminal. В отличие от `--bare`, этот режим сохраняет обычную авторизацию подписки. Отключены пользовательские инструкции CLAUDE.md, плагины, навыки и память CLI; контекст и инструменты задаёт Dewiar. `--setting-sources ""`, пустые tools и строгая пустая конфигурация MCP сохранены. Старому CLI без поддержки safe-mode потребуется обновление.

При исходном запуске из GUI macOS ожидала разрешения на «Документы», что приводило к тайм-ауту. С загрузкой пользовательских дополнений, отключённой через safe-mode, настоящее ядро финальной .app распознало аккаунт, вернуло каталог из 13 моделей и ответ haiku «Готово.» за 2,827 с. В окне подтверждены «Вход выполнен», заполненный список Claude и активная кнопка «Использовать». Вход сам по себе не переключает активную модель.

Пройдены 17 тестов транспорта, security1019_test, macos_chat_test, нативная проверка исходников и собранной .app, проверка подписи. Нативный сценарий проверяет завершение входа из Terminal без события focus и остановку опроса при local_only. API-ключи и пользовательская переписка в живых проверках не использовались.

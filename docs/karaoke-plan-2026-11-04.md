## 1. Результат и границы

**Что получает пользователь.**
- В карточке песни есть действие **«Подготовить минусовку»** с ходом выполнения, отменой и понятной ошибкой.
- В существующем плеере появляется переключатель **«Оригинал / Минусовка»**. Переключение сохраняет позицию и состояние «играет/пауза», подсветка слов продолжается без сдвига.
- Для каждой из девяти песен минусовка подготовлена, прослушана пользователем и имеет оценку: «годится», «годится с дефектами» (дефекты названы) или «не годится».
- **Минусовка с бэк-вокалом** — дополнительный вариант для песен, где это имеет смысл (5.2, 7).

**Что не входит:** новый экран, полный экран, изменение тональности звука, регулятор громкости исполнителя, экспорт, запись своего голоса — всё это в отложенном документе.

**Главный принцип.** Качество минусовки определяется не названием модели, а результатом на этих конкретных записях. Поэтому:
1. отбор моделей идёт по объективным проверкам (раздел 6);
2. окончательное решение принимает пользователь слепым прослушиванием (6.6);
3. выбор фиксируется для каждой песни.

## 2. Что такое «правильная минусовка»

| Дефект | Как проявляется | Почему важно для караоке |
|---|---|---|
| Остаточный голос («призрак») | Слышны слова, шипящие «с/ш/ч», вдохи, обрывки гласных | Хуже всего: исполнитель подпевает поверх пользователя. Приоритет № 1 |
| Хвост реверберации голоса | Эхо после каждой фразы | Заметно в паузах между строками |
| Потеря инструментов | Гитара тише или глуше в куплете, пропали атака струн, верх, скрипка или саксофон в диапазоне голоса | Для песен «гитара и голос» почти так же важно, как остаток голоса |
| Бэк-вокал и хор | Удалены вместе с ведущим голосом или, наоборот, остались | Решается выбором варианта: чистая или с бэком |
| Артефакты обработки | «Водянистый», «булькающий» звук, провалы громкости на месте голоса | Утомляет при длительном пении |
| Технические ошибки | Другой уровень, длина, сдвиг по времени, клиппинг, моно вместо стерео, срез верхних частот | Сдвиг ломает подсветку слов; разный уровень — скачок громкости при переключении |

Порядок приоритетов при выборе: нет разборчивого голоса → инструменты целы → нет заметных артефактов. Для песен «гитара и голос» второй пункт весит почти как первый. Обзор метрик MVSEP формулирует то же правило: для караоке сначала смотреть на **Bleedless** (сколько голоса осталось), для игры вместе с записью — на **Fullness** (сколько музыки сохранено). [Обзор, 22.10.2026](https://uvrvocalremover.com/blog/best-uvr-model-for-instrumental).

## 4. Вход: качество исходной записи

Минусовка не может быть лучше исходника. Для каждой песни до разделения (ffprobe + анализ спектра) записываются:
- **Формат:** кодек, частота, каналы, длительность, битрейт.
- **Фактическая полоса:** частота, выше которой энергии почти нет. Например, срез на 16 кГц указывает на сильное сжатие.
- **Уровни:** громкость по EBU R128 и истинный пик; есть ли клиппинг в самом исходнике.
- **Моно или стерео:** признак «двойное моно» — каналы совпадают с точностью до шума.

**Правила:**
- Лестница качества: файл без потерь → захват Яндекс Музыки в музыкальном режиме (декодированный поток 44,1/48 кГц стерео) → YouTube (Opus/AAC). Сжатие с потерями даёт свои артефакты, и разделение их усиливает: остаток голоса в сжатом файле убрать труднее.
- Если находится лучший исходник того же исполнения (та же длительность, исполнитель и версия), минусовка готовится из него. Карточка не подменяется без подтверждения: синхронизация слов привязана к текущей записи, поэтому для нового исходника проверяется совпадение по времени (взаимная корреляция; допустимый сдвиг пересчитывается в смещение).
- 16 кГц или 1 канал из старого речевого захвата — минусовка не готовится, предлагается записать заново.
- Моно (архив) — обрабатывается как двойное моно, результат — моно; так и показывается.

### 5.2. Варианты минусовки

- **`instrumental` — чистая.** По умолчанию: голос и бэк удалены.
- **`instrumental_bv` — с бэк-вокалом.** Через караоке-модель. Готовится по явному выбору. Полезна, когда бэк и хор — часть музыки. Не подходит, когда поют два равноправных ведущих голоса: модель может удалить один из них и оставить второй.
- **`vocals` — дорожка голоса.** Побочный результат. Хранится для проверок (6.5) и будущего регулятора громкости исполнителя.

## 6. Конвейер подготовки

```text
исходник → проверка входа (4) → декодирование → разделение кандидатами → формула инструментала
        → (необязательно) подавление остатка → выравнивание уровня, длины и времени
        → объективные проверки → слепое прослушивание → выбор → мастер FLAC → manifest
```

### 6.1. Декодирование

- ffmpeg → WAV float32, без нормализации, компрессии и дизеринга.
- Если частота не 44,1 кГц — передискретизация soxr высокой точности (`aresample=resampler=soxr:precision=28`). Исходная частота записывается.
- Моно → два одинаковых канала, флаг `mono_source`.
- Перед разделением добавляется 1 с тишины в начало и конец: края фрагментов дают артефакты. После разделения обрезается с точностью до сэмпла.

### 6.2. Разделение

- **audio-separator в отдельном runtime** (раздел 9), через Python API, не через CLI в интерфейсе.
- **Нормализация.** По README `normalization` по умолчанию 0,9 — «максимальный пик входа и выхода». Это может изменить уровень, поэтому в пилоте проверяется сумма `instrumental + vocals ≈ mix` (6.4) при разных значениях. Выбирается настройка, при которой уровень сохраняется; иначе уровень восстанавливается по 6.4.
- **Формат выхода** — WAV/float или FLAC без потерь, частота 44 100 (`sample_rate` по умолчанию 44 100).
- **Параметры RoFormer/MDXC** фиксируются для каждой модели и входят в ключ кэша:
  - `mdxc_segment_size` — по умолчанию 256;
  - `mdxc_overlap` — по README от 2 до 50, по умолчанию из YAML модели;
  - `mdxc_batch_size`.

  Значения 4 и 8 overlap сравниваются в пилоте: README предупреждает, что большие значения дают больше проходов и время.
- **`mdxc_pitch_shift`.** По README может улучшить результат для низких и высоких голосов. Пробуется только для песен, где остался голос (низкие мужские голоса: Высоцкий, Розенбаум).
- **Устройство.** README: модели PyTorch используют MPS, неподдерживаемые комплексные операции уходят на CPU; есть переменные `AUDIO_SEPARATOR_MPS_BUFFER_BUDGET_GIB` и `AUDIO_SEPARATOR_FORCE_CPU_COMPLEX`. Результат MPS сравнивается с CPU на одном отрывке: разница дорожек ниже −60 дБ относительно сигнала. При расхождении используется CPU, и это отмечается.
- **Ансамбли.** audio-separator умеет ансамбль (`--extra_models`, `--ensemble_algorithm`: `avg_wave`, `median_wave`, `avg_fft`, `uvr_max_spec`, `uvr_min_spec` и др.) и готовые пресеты `instrumental_clean`, `instrumental_balanced`, `instrumental_full`, `karaoke`. В пилоте проверяются два ансамбля:
  - `avg_wave` из «bleedless» и «fullness» моделей;
  - пресет `instrumental_balanced`.

  Ансамбль берётся, только если прослушивание показало пользу: он в несколько раз дольше.

### 6.3. Формула инструментала

Для каждого кандидата сохраняются и сравниваются:
1. **`model`** — инструментал, который выдала модель.
2. **`residual`** — `mix − vocals`. Сохраняет всё, что модель не сочла голосом (меньше потерь музыки), но может содержать больше остатка голоса.
3. **`phase_fixed`** — амплитуда спектра из `model`, фаза из `residual`: STFT 4096/1024, затем ISTFT. Так устроен пресет MVSEP «Phase-corrected instrumental»: амплитуда инструментала модели, фаза остатка «микс минус голос». Цель — убрать «водянистость», не возвращая голос. Реализуется в numpy, проверяется прослушиванием.

Для HTDemucs вместо `model` берётся `drums + bass + other`.

**Подавление остатка.** Bleed Suppressor — вторым проходом, только для финалистов, у которых в 6.5 найден разборчивый голос. Сравнивается «до/после»: подавитель может съесть и часть музыки.

**Хвосты реверберации голоса** отдельной обработкой инструментала не убираются: удаление реверберации заберёт и реверберацию инструментов. Если эхо слышно, выбирается кандидат с лучшим Bleedless или подавитель остатка.

### 6.4. Уровень, длина и время

- **Длина** — ровно как у исходника в сэмплах (после обрезки полей 6.1).
- **Сдвиг.** Взаимная корреляция инструментала и исходника на участках без голоса (6.5), окно ±2048 сэмплов. Ожидается 0; ненулевой сдвиг исправляется и записывается. Без этого подсветка слов поедет при переключении.
- **Уровень.** На участках без голоса инструментал должен совпадать с исходником, поэтому коэффициент `g = Σ(inst·mix)/Σ(inst²)` должен быть ≈ 1. Если |20·log₁₀ g| > 0,2 дБ — это изменение уровня обработкой: исправить умножением и отметить в manifest.
- **Сумма.** Для моделей, выдающих обе дорожки: `mix − (inst + vocals)` по энергии должен быть ниже −30 дБ относительно `mix`. Иначе модель или обработка что-то потеряли.
- **Пик.** Истинный пик (ffmpeg `ebur128=peak=true`). Если инструментал выше −0,1 dBTP, в мастер пишется ослабление, а для оригинала при воспроизведении ставится тот же `playback_gain_db`. Так уровни при переключении совпадают, и ничего не клиппирует. Громкость `<audio>` может только уменьшать.

### 6.5. Объективные проверки без эталона

Эталонных дорожек нет, но у песни есть времена слов. Из них строятся:
- **участки с голосом** — объединение интервалов слов ±150 мс;
- **участки без голоса** — вступление, проигрыши, концовка длиной ≥ 1 с, с отступом 300 мс от голоса (хвосты реверберации).

Для каждого кандидата и песни считаются четыре проверки.

1. **Сохранность музыки без голоса.** `SDR_нг = 10·log₁₀(Σmix² / Σ(mix − inst)²)` на участках без голоса. Там ничего не должно убираться, поэтому низкое значение значит, что модель режет инструменты.
   - Порог «тревоги» устанавливается на пилоте; ориентир — ниже 20 дБ.
   - Для песен без таких участков (46-секундная «Правда ведь, обидно») проверка недоступна, и это указывается.
2. **Остаток голоса по повторному разделению.** Инструментал кандидата заново разделяется моделью другого семейства (для RoFormer — HTDemucs, для HTDemucs — Kim MelBand) и считается энергия «голоса» на участках с голосом:
   `R = 10·log₁₀(E(голос из inst) / E(голос из mix))`, дБ, меньше — лучше.
   Контрольный уровень — тот же показатель на участках без голоса: проверяющая модель может принять гитару за голос.
3. **Разборчивые слова.** Быстрый установленный распознаватель (Whisper large-v2 MLX или GigaAM) запускается на инструментале по участкам с голосом, и считаются слова, совпавшие с текстом песни (нормализация как в ASR песен, нечёткое совпадение ≥ 0,8): «осталось разборчивых слов N из M».
   Чтобы отделить распознавание голоса от «галлюцинаций» на музыке, тот же распознаватель запускается на участках без голоса исходника; число найденных там слов — фон.
   Для караоке это самая прямая проверка: исполнитель, которого можно разобрать, мешает больше всего.
4. **Технические:** NaN/Inf, клиппинг, длина, сдвиг, уровень (6.4), полоса частот относительно исходника, моно/стерео.

Проверки ранжируют кандидатов и указывают, что слушать. Итоговое решение принимается прослушиванием.

### 6.6. Слепое прослушивание пользователем

- **Отрывки** — 4 фиксированных по 20 с: начало, первый куплет, самый плотный припев (по энергии), конец.
- **Сравнение.** 2–3 финалиста по 6.5 плюс оригинал как опора. Кандидаты подписаны A/B/C в случайном порядке; название модели скрыто до выставления оценок. Переключение A/B/C идёт в той же позиции.
- **Оценки по отрывку:**
  - голос: не слышен / еле / слышен / разборчив;
  - музыка: цела / немного потеряна / заметно потеряна;
  - артефакты: нет / есть;
  - лучший вариант.
- **Время** — 5–8 минут на песню, около часа на девять.
- **Хранение.** Оценки записываются в manifest и отчёт и не меняются при последующих автоматических пересчётах.

### 6.7. Правило выбора

1. Отбросить кандидатов, у которых хотя бы в одном отрывке голос «разборчив» или музыка «заметно потеряна».
2. Из оставшихся — лучший по оценкам пользователя. При равенстве — меньший остаток голоса (6.5, п. 2–3), затем меньше дефектов.
3. Если не осталось никого — лучший из имеющихся с явной пометкой «с дефектами» и списком дефектов; пользоваться им можно.
4. **Модель по умолчанию для новых песен** — та, что выиграла на большинстве из девяти, с учётом жанра: отдельно «гитара и голос» и «аранжировка».

### 6.8. Мастер и выдача

- **Мастер:** FLAC 24 бита, 44,1 кГц, каналы как у исходника.
- **Объём:** примерно 9–10 МБ на минуту стерео — уточнить измерением. Для 4-минутной песни инструментал и голос — порядка 75 МБ, девять песен — меньше 1 ГБ.
- **Для плеера** `song_full_audio {variant}` кодирует оригинал и минусовку **одинаково** (MP3 CBR 128 кбит/с, 44,1 кГц). Задержка кодера у обеих дорожек одна, поэтому при переключении нет сдвига.
- **Кэш MP3.** Готовый MP3 кэшируется рядом с мастером (ключ — sha мастера и параметры кодирования), чтобы не кодировать при каждом нажатии.
- **Проигравшие кандидаты** удаляются после выбора; их метрики и оценки остаются в отчёте.

## 8. Подключение к существующему плееру

- **Карточка песни.** Иконка «Минусовка» с состояниями:
  - нет;
  - в очереди;
  - этап: декодирование, разделение (процент — только если модель сообщает прогресс), проверки;
  - готова (модель, дата);
  - с дефектами;
  - ошибка (причина и действие).

  Есть отмена. При отсутствии runtime — «Модуль минусовки не установлен» и отдельная кнопка установки с размером (раздел 9).
- **Переключатель «Оригинал / Минусовка»** — рядом с кнопками плеера в `song_review.js`. Переключение:
  1. запомнить `position = clipStart + currentTime·1000` и «играет/пауза»;
  2. загрузить дорожку `song_full_audio {song_id, variant}`;
  3. дождаться `canplay`, перемотать на `position`, продолжить, если играло.

  Во время загрузки показывается «Переключаем…»; поздний ответ после стопа не запускает звук. Подсветка слов не меняется: время у дорожек общее (6.4).
- **Кэш в памяти.** Обе дорожки текущей песни хранятся в памяти как `data:`-URL (около 4–6 МБ каждая для 4 минут), поэтому повторные переключения мгновенные. При смене песни кэш освобождается.
- **Запоминание.** Последний выбранный вариант хранится в данных песни (`presentation.variant`), не в settings.json.
- **«Сравнить варианты»** — меню карточки, режим слепого прослушивания 6.6. Используется и для пилота, и потом, если пользователь захочет переделать минусовку другой моделью. Новый результат не заменяет текущий, пока пользователь его не выберет.
- **Длинные песни.** Предел `song_full_audio` — 10 минут. Для более длинных песен — сообщение «Слишком длинная для текущего плеера»; медиасервер в отложенном документе.

## 9. Runtime разделения

- **Окружение.** Отдельное `~/Library/Application Support/Dewiar/runtimes/separation/` (Python 3.12). Окружения ASR и `.venv` не трогаются.
  - audio-separator с закреплённой версией.
  - По README для Apple Silicon нужны PyTorch ≥ 2.13 и < 3, macOS Sonoma или новее, M1 или новее. В `.songs-separation-venv` сейчас torch 2.11, поэтому его не обновлять на месте, а создать новое окружение.
- **Установщик** `tools/install_song_separation.py` — по образцу `install_song_models.py`:
  - только выбранные модели, со скачиванием с проверкой SHA-256 и возобновлением недокачанного файла;
  - `separation-models.json` с версиями, ревизиями, лицензиями и источниками;
  - веса HTDemucs из существующего кэша используются без копирования.
- **Worker.** Запуск с `-B`, `PYTHONDONTWRITEBYTECODE=1` и офлайн-флагами (правила `AGENTS.md`). При открытии карточки ничего не скачивается. После работы worker в установленной `.app` — `codesign --verify --deep --strict`.
- **Ресурсы.** Одна тяжёлая задача на всю очередь песен (разделение, ASR, выравнивание). Пиковая память и время на песню измеряются на этапе М0 и записываются в отчёт; при нехватке памяти — понятная ошибка и предложение CPU или меньшего overlap.
- **Лицензии.** Код audio-separator — MIT. Лицензии весов сообщества UVR/MVSEP часто не указаны. Использование личное, некоммерческое; источник и известная лицензия каждой модели записываются в manifest.

## 10. Данные и хранение

`STATE/songs/<song_id>/karaoke/manifest.json` — пример формата, не текущий API:

```json
{
  "schema_version": 1,
  "source": {"sha256": "…", "codec": "opus", "sample_rate": 48000, "channels": 2, "lossy": true,
             "bandwidth_hz": 16000, "mono_source": false, "loudness_lufs": -13.9, "true_peak_db": -0.4},
  "selected": {"instrumental": "cand-3", "instrumental_bv": null},
  "candidates": [{
    "id": "cand-3", "model": "mel_band_roformer_kim_ft2_bleedless_unwa.ckpt", "weights_sha256": "…",
    "runtime": "audio-separator==…", "device": "mps", "params": {"overlap": 4, "segment_size": 256, "pitch_shift": 0},
    "formula": "model|residual|phase_fixed", "bleed_suppressor": false,
    "checks": {"sdr_no_voice_db": 27.1, "residual_voice_db": -31.5, "words_left": [2, 143],
               "offset_samples": 0, "gain_db": 0.0, "clipped_samples": 0},
    "listening": {"verdict": "ok|defects|bad", "notes": "…", "by": "user", "at": "…"},
    "artifacts": {"instrumental": "…flac", "vocals": "…flac"}, "seconds": 0, "peak_memory_mb": 0
  }],
  "playback_gain_db": {"original": 0.0, "instrumental": 0.0},
  "presentation": {"variant": "instrumental"}
}
```

- **Ключ кэша** — sha исходника, модель и веса, параметры, формула, версия конвейера. Правка текста не требует нового разделения: участки голоса для проверок 6.5 пересчитываются без него.
- **Запись артефактов** — во временный каталог, проверка, атомарная замена manifest. Блокировка по песне исключает двойную обработку. Отмена завершает только процесс этой задачи; готовые кандидаты остаются.
- **Хранение.** Класс `karaoke` (минусовка, голос, MP3-кэш) живёт до явного «Удалить минусовку» или удаления в «Освободить место».
  - Правило плана песен «удалить дорожку голоса после проверки текста» на песни с минусовкой не действует.
  - Оригинал хранится по общему правилу (`AGENTS.md`: до проверки текста и аккордов или явного удаления).
  - Удаление оригинала при готовой минусовке разрешено, но предупреждает, что переделать минусовку будет нельзя.
- **Настройки.** Settings.json не меняется. Состояние минусовки — в данных песни; список песен получает только краткий статус.

| Этап | Дни | Содержание и условие перехода |

## 12. Критерии приёмки

1. **Девять песен.** У каждой есть выбранная минусовка с вердиктом пользователя или явная пометка «не годится» с причиной. Отчёт содержит для каждой: исходник, кандидатов, проверки 6.5, время и память, оценки прослушивания.
2. **Время.** Длина минусовки равна исходнику до сэмпла, сдвиг 0. Переключение «Оригинал ↔ Минусовка» в любой точке продолжает с той же позиции (±50 мс на слух и по `currentTime`), подсветка слов не сдвигается.
3. **Уровень.** На участках без голоса разница уровней оригинала и минусовки ≤ 0,5 дБ; клиппинга нет.
4. **Остаток голоса.** У выбранной минусовки нет отрывков с оценкой «разборчив». Число разборчивых слов (6.5, п. 3) записано и не выше фона больше чем на заметную величину; порог фиксируется после М2.
5. **Плеер.** Пауза, стоп, переходы по строкам, конец песни и смена песни работают на обеих дорожках. После стопа поздний ответ не включает звук. Повторное переключение — без новой загрузки.
6. **Задачи.** Отмена, повторный запуск, перезапуск приложения во время разделения, нехватка места и отсутствие runtime дают понятное состояние. Готовые кандидаты не теряются, незавершённый результат не становится активным.
7. **Безопасность установки.**
   - Открытие карточки не скачивает и не устанавливает модели.
   - Контрольная сумма settings.json не меняется.
   - Тесты — в изолированных CONFIG/STATE/WORKSPACE, общий `unittest discover` не используется.
   - `codesign --verify --deep --strict` после работы worker в `.app`.
8. **Хранение.** Проверка текста не удаляет минусовку и голос. «Удалить минусовку» освобождает показанный объём и не трогает оригинал.

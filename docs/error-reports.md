# Доставка сообщений об ошибках

Жучок в главном окне открывает форму. Само нажатие ничего не отправляет. Кнопка «Отправить разработчику» отправляет описание, технический отчёт и выбранный снимок.

Порядок доставки:

1. Если в «О программе → Адрес сервера обработки ошибок» задан собственный адрес, отправляется HTTPS POST на этот точный URL. При необходимости используется отдельный ключ сервера отчётов. Ключ облака Dewiar не используется.
2. Если сервер не задан или не подтвердил приём, письмо отправляется через почту, подключённую в «Подключение → Почта». Получатель — **domatskevich@gmail.com**, тема — **Ошибка обработки персональный агент**. Отчёт прикрепляется как UTF-8 `report.txt`; выбранный снимок — как `screenshot.jpg`. В тело включаются описание и идентификатор отчёта.
3. Если почта не подключена, сеть недоступна или отправка запрещена режимом безопасности, отчёт остаётся локально со статусом «ожидает отправки». После подключения почты/сети нажмите «Повторить отправку». Фоновая отправка очереди при запуске не выполняется.

Письмо требует настроенного ящика отправителя: адрес получателя сам по себе не даёт возможности отправлять почту. Пароли не нужно сообщать в чате; настройка выполняется в интерфейсе Dewiar. Неподтверждённая отправка никогда не показывается как успешная. Подтверждение SMTP означает приём письма почтовым сервером отправителя, а не доказательство доставки во входящие адресата.

Отдельный сервер задаётся в `report.server_url`, необязательный ключ — в `report.server_key`. Внешний адрес требует HTTPS; для тестового/домашнего сервера допустим локальный HTTP. URL не должен содержать логин, пароль, параметры или фрагмент. Переходы по HTTP redirect не выполняются. Отключение сервисов dewiar.pro сохраняется; собственный сервер и SMTP не включают их. Режим «только локально» продолжает запрещать внешние подключения. Согласие на автоматические отчёты не изменяется этой функцией.

## Контракт будущего сервера

POST на настроенный URL, `Content-Type: application/json`. Поля:

- `report_id`: UUID без дефисов — постоянный идентификатор доставки;
- `kind`: `manual` или `auto`;
- `app`, `version`, `os`, `device`;
- `summary`, `note`, `text`;
- необязательные `who` и `shot` (`data:image/jpeg;base64,...`).

Заголовки: `Idempotency-Key: <report_id>`; при заданном ключе — `Authorization: Bearer <server_key>`.

Успех: HTTP 2xx и `{"ok":true,"id":"идентификатор"}`. Поле `secret` необязательно, сохраняется приватно и не показывается в списке доставки. Ожидание сервера — до 10 секунд. Сервер должен обрабатывать `Idempotency-Key`, чтобы повтор одного отчёта не создавал дубликаты.

При тайм-ауте сервер мог принять запрос до обрыва связи; резервное письмо будет содержать тот же `report_id`. Аналогично SMTP-обрыв после передачи письма может оставить результат неопределённым. Автоматического повтора очереди нет; ручной повтор использует прежние идентификатор отчёта и Message-ID письма, но почтовые серверы не обязаны удалять такие дубликаты. После подтверждённой доставки повтор из очереди не отправляет письмо заново.

Локальная очередь: `state/report-outbox/<report_id>.json`, файлы с правами 0600. После подтверждения доставки из файла удаляются текст отчёта и снимок, остаётся статус. Неотправленные данные сохраняются для повтора, до 100 отчётов. Серверные ответы по статусам/комментариям для собственного сервера пока не реализованы; отправка письма также не обещает автоматического получения ответа в приложении.

Проверки: `report_delivery_test.py` (локальные заглушки), `report_delivery_flow_test.py` (настоящее ядро, локальный HTTP и локальный SMTP; также `--bundle`), нативный Cocoa/WebKit smoke формы. Проверяются тема «Ошибка обработки персональный агент», адрес, UTF-8, вложения, сервер как основной путь, резервный SMTP, очередь, повтор, отсутствие ложного успеха и сохранение сетевых запретов. Реальные письма не отправляются.

# AudioTranscripts (ushi) → Dewiar: что взято и почему

Источник: [github.com/raliev/audiotranscripts](https://github.com/raliev/audiotranscripts) (версия 1.4.0 от 28.10.2026) и [статья автора](https://hybrismart.com/2026/10/25/voice-screen-local-models/). Продолжение `meeting-recording-review-v2.md`.

Актуализация 30.10.2026: адрес GitHub перенаправляется на `raliev/ushi`. Swift-хелпер уже собран на Mac и прошёл `--list` и синтетический `--self-test`; [результаты интеграции и ограничения](meeting-recording-review-v3.md). Ниже сохранено сравнение исходной экспертной итерации, поэтому её отметки «не собирался» и «следующие шаги» нужно читать с учётом v3.

## 0. Лицензия — прочитать первым

В репозитории **нет файла LICENSE** и упоминания лицензии в README. По умолчанию код защищён авторским правом, поэтому в Dewiar он **не копировался**. Взяты только идеи и подходы, а реализация написана заново под протокол Dewiar. Если понадобится дословно перенести что-то крупное (например, оверлей выбора области и окна из `screenshot_helper.swift`), сначала нужно попросить автора добавить лицензию (MIT/Apache-2.0) или получить разрешение.

## 1. Сравнение

| Тема | Dewiar до v2 | ushi | Dewiar сейчас |
|---|---|---|---|
| Звук собеседника на Mac | BlackHole + ручной Multi-Output | Core Audio Process Tap, Swift-хелпер `audio_helper`, без драйвера | Swift-хелпер `dewiar-audio-tap` (своя реализация), BlackHole — запасной путь |
| Чей звук | Весь вывод через BlackHole | Одно приложение (`app:<bundle>`), вспомогательные процессы сгруппированы по `.app` | `all` — всё, кроме самого Dewiar (его голос не попадает в запись), или выбранные bundle id |
| Смена наушников и процессов звонка | Не обрабатывалась | Пересоздание tap раз в секунду | Так же, плюс переоткрытие BlackHole и микрофона в Python |
| Часы | Время стены, пропуски на паузе | Выдача по часам, тишина — нулями; время фразы — по номеру отсчёта | Так же: хелпер выдаёт поток по часам, пауза пишет тишину, реплики получают время по номеру отсчёта |
| Вы / Собеседник | Микрофон выключался | `app+mic`: два канала, у каждого свой VAD, метки `[Me]`/`[Them]` | Две дорожки WAV + общий, у каждой свой VAD, подавление эха |
| Нет разрешения на звук | — | macOS молча отдаёт нули → предупреждение | Хелпер сообщает `warning:zeros`; детектор тишины; подсказки различаются для tap и BlackHole |
| Распознавание | GigaAM / Vosk / модель Dewiar | Whisper (по умолчанию), GigaAM v3, Parakeet через onnx-asr | Без изменений: GigaAM уже лучший вариант для русского (у автора 4,4 с против 90 с у Whisper на 140 с речи) |
| Автокадры | Сравнение 32×18 с прошлым тактом, порог 1,2 % | Каскад: устоявшийся экран 1,5 с → сцена (3 % или «редкий» слайд) → возврат к прошлому слайду → CLIP | Уровень 0 каскада перенесён (96×54, устоявшийся экран, сцены, редкие слайды, возвраты к 12 последним) |
| Итог | Хвост 24 000 знаков | Части ~25 000 знаков по самой длинной паузе; OCR как справочник для исправления имён и терминов | Части по 18 000 знаков, разрез по самой длинной паузе; OCR — справочник; таймкоды |
| Сырые данные для повторной обработки | Нет | `.raw.txt`, `.pkl` для `rediarize.py` | `Расшифровки/<имя>.lines.json` (реплики + метаданные + пути дорожек) |
| Аудио в памяти | Пишется на диск по ходу | Копится в RAM, WAV/MP3 — при остановке | Остаётся на диске по ходу: падение не теряет запись. **Здесь подход Dewiar лучше** |

## 2. Что сделано в коде

| Файл | Изменение |
|---|---|
| `native/macos/dewiar_audio_tap.swift` | Новый хелпер: `--list` (JSON приложений со звуком); `--capture all [--exclude-pid N]` или `--capture <bundle,…>`. В stdout идёт s16le 16 кГц моно по часам, в stderr — JSON-события `ready/status/tap/warning/error`. Tap и приватный aggregate device пересоздаются при смене устройства вывода или процессов. Есть перезапуск хелпера ответственным процессом при запуске из исходников (иначе TCC отдаёт нули) |
| `native/macos/dewiar_audio_tap.Info.plist` | `NSAudioCaptureUsageDescription`; вшивается в бинарник |
| `tools/build_audio_tap.sh` | Сборка `native/macos/bin/dewiar-audio-tap` (arm64/x64, macOS 14.2+), подпись `DEWIAR_CODESIGN_IDENTITY` или ad hoc, самопроверка `--list` |
| `packaging/macos.spec` | Хелпер кладётся в `.app` (`native/`); в Info.plist Dewiar добавлен `NSAudioCaptureUsageDescription` |
| `core/audio_io.py` | `TapCapture`, `audio_tap_path()`, `audio_tap_supported()`, `list_audio_apps()`. `LoopbackCapture(backend=auto/tap/blackhole, tap_target=…)` сначала пробует tap, затем откатывается на BlackHole; `probe()` проверяет без записи и без системного запроса |
| `core/prompter.py` | Настройки `prompter.system_audio` (`auto`) и `prompter.tap_target` (`all`); предупреждения хелпера в статусе и событии `warning`; подсказки о тишине по способу записи. Каскад автокадров; время реплик по номеру отсчёта; время строки «Экран» — по часам записи. OCR как справочник в итоге; разрез частей по паузе; `.lines.json` |
| `tests/prompter_dual_track_test.py` | Блоки 11–13: протокол хелпера (подменён скриптом), каскад кадров, справочник OCR, разрез по паузе, `lines.json` |

Все тесты встреч проходят в Linux-окружении. **Swift-хелпер не собирался**: здесь нет macOS. Это первое, что нужно проверить.

## 3. Что сознательно не перенесено

- **Whisper и подсказки словаря.** Пока сохраняем существующий GigaAM/Vosk pipeline. Приведённые автором скорости относятся к его стенду; фиксированное ускорение в 20 раз и отсутствие ошибок на тишине на нашем Mac не подтверждены. Для выбора движка нужен сопоставимый набор записей.
- **Диаризация SpeechBrain ECAPA (torch).** В онлайн-встрече «Вы»/«Собеседник» теперь известны по дорожкам. Кластеризация нужна только для нескольких собеседников на одной дорожке; это отдельный этап, и тянуть ради него torch в `.app` невыгодно. Идею «кластеризация один раз после остановки + сырые данные для повторного запуска» стоит взять, когда до этого дойдёт.
- **CLIP (уровень 1 каскада).** Это полезно (выбросить кадры с лицами, склеить похожие), но добавляет модель на ~600 МБ. Сначала нужно проверить, хватает ли уровня 0.
- **Горячие клавиши и «выделенный текст» через имитацию Cmd+C.** Такой способ портит буфер обмена (автор сам об этом пишет). Если делать, то через Accessibility API (`AXSelectedText`), без подмены буфера.
- **Снимки через `CGWindowListCreateImage`.** API устарел с macOS 14; в Dewiar его место займёт ScreenCaptureKit (`SCScreenshotManager`) в том же Swift-хелпере.
- **Веб-сервер.** У автора была уязвимость: сервер отвечал любой странице браузера, это закрыли ограничением localhost. В Dewiar уже авторизованный WebSocket — проверьте только, что команды встречи (`prompter_*`) нигде не доступны без токена.

## 4. Сборка и приёмка на MacBook

```sh
cd ~/Documents/dewiar/app
tools/build_audio_tap.sh                      # → native/macos/bin/dewiar-audio-tap
native/macos/bin/dewiar-audio-tap --list      # приложения со звуком (разрешение не нужно)
# 10 секунд звука системы → WAV для прослушивания (включите любое видео):
native/macos/bin/dewiar-audio-tap --capture all > /tmp/tap.raw & sleep 10; kill %1
ffmpeg -f s16le -ar 16000 -ac 1 -i /tmp/tap.raw /tmp/tap.wav && open /tmp/tap.wav
```

При первом `--capture` macOS спросит «Запись системного звука». Если в `/tmp/tap.wav` тишина, а в stderr есть `"code":"zeros"`, значит разрешение не выдано: «Конфиденциальность и безопасность → Запись экрана и системного звука».

Затем:
1. Запустите Dewiar из исходников (`tools/run_macos.sh`) и начните онлайн-встречу с записью. В статусе должно быть «звук системы (кроме Dewiar) через Core Audio», а BlackHole можно удалить.
2. Во время звонка смените наушники на колонки и обратно: запись не прерывается, в журнале есть `tap` с новым устройством.
3. Включите голосовой ответ Dewiar во время записи: его голоса нет в `Собеседник.wav` (исключение `--exclude-pid`).
4. Выберите `prompter.tap_target = us.zoom.xos` (или bundle Телемоста/браузера): музыка из другого приложения не пишется.
5. Покажите презентацию с автокадрами: во время перелистывания промежуточные кадры не сохраняются, а возврат к слайду не создаёт новый файл.
6. Соберите `.app`: `tools/build_audio_tap.sh` до PyInstaller, затем убедитесь, что хелпер лежит внутри (`Contents/Frameworks/native/dewiar-audio-tap`) и разрешение запрашивается от имени Dewiar.

Для сравнения можно запустить и сам ushi рядом: `./compile.sh`, затем `python main.py --source app+mic:us.zoom.xos --engine gigaam --auto-frames 1`. Это удобный эталон для проверки, что tap Dewiar слышит то же самое.

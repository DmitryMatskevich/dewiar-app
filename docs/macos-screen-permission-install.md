# Снимок экрана: установленная сборка и разрешения macOS

## Проверка 1 ноября 2026 года

Наблюдалось: в macOS включена запись экрана для Dewiar, но реальный
`CGPreflightScreenCaptureAccess()` возвращал отказ и кнопка снимка показывала ошибку.
Сборка запускалась из `app/dist/Dewiar.app`, подпись — ad hoc, bundle id —
`pro.dewiar.macos`, designated requirement привязан к cdhash. Действительных
сертификатов `security find-identity -v -p codesigning` не обнаружено.

Обычный перезапуск и выключение/включение переключателя записи экрана не помогли.
После закрытия окна оставались отдельные процессы `--core --server`.

Выполнено:

1. Закрыто приложение и завершены процессы ядра именно этой .app.
2. Текущая проверенная сборка скопирована в `/Applications/Dewiar.app`.
3. В настройках macOS удалена старая запись Dewiar из списка записи экрана
   и добавлен `/Applications/Dewiar.app`.
4. Запущена установленная копия. Кнопка «Приложить снимок экрана» создала
   реальное вложение с миниатюрой. Сообщение и снимок в модель не отправлялись.

Это подтверждает восстановление захвата у текущей сборки. Отдельно влияние пути
и повторной регистрации не измерялось: сами по себе приложения вне Applications
не запрещены macOS.

## Последующие обновления

Использовать `tools/rebuild_mac_app.command`: после сборки и проверки он
устанавливает приложение в `/Applications/Dewiar.app` и запускает эту копию.
Установщик `tools/install_mac_app.py` проверяет bundle id и подпись, не заменяет
запущенные копии, предварительно копирует и проверяет новую сборку, сохраняет
предыдущую версию и возвращает её при ошибке финального переименования.
Файлы приложения заменяются целиком, пользовательские данные не перезаписываются.

Для установки уже готовой сборки после полного завершения Dewiar:

```sh
.venv/bin/python tools/install_mac_app.py
```

Установщик не сбрасывает TCC и не выдаёт системные разрешения автоматически.
При смене ad-hoc идентичности он предупреждает о возможном повторном разрешении;
смена постоянной идентичности требует отдельного решения и останавливает установку.

Постоянный путь не гарантирует сохранение разрешений после пересборки с ad hoc.
Для этого нужна постоянная Apple Development / Developer ID Application подпись:
см. [подготовку подписи](macos-microphone-signing.md). Сертификат сейчас отсутствует;
сохранение разрешений между разными сборками пока не подтверждено.

Если переключатель включён, но текущая сборка всё ещё получает отказ, после
полного завершения приложения удалите только запись Dewiar в «Запись экрана»,
добавьте установленную копию и запустите её снова. Другие приложения не затрагивать.

Проверки установщика: `tests/macos_install_test.py` — полная замена без устаревших
файлов, резервная копия, откат при ошибке замены, запрет понижения постоянной подписи.

## Исправление 3 ноября 2026 года

Повторно подтверждено: установленная сборка подписана ad hoc (`designated => cdhash`),
`security find-identity -v -p codesigning` не находит постоянных сертификатов.
В системном списке была видна запись `previous`: прежний установщик перемещал
приложение в `previous.app`. Это создавало ещё одну запускаемую копию с тем же bundle id.

Новый установщик сохраняет inode и путь `/Applications/Dewiar.app`, заменяет её
`Contents` после проверки, проверяет установленную подпись и возвращает старое
содержимое при ошибке. Резервная копия — `previous.zip`, а не приложение в списке
LaunchServices. Резервирование `dist` также использует ZIP. Старые резервные копии
от предыдущих запусков автоматически не удаляются.

После запуска Cocoa основной процесс установленной программы проверяет реальный
`CGPreflightScreenCaptureAccess`. Если доступа нет, вызывает системный
`CGRequestScreenCaptureAccess` один раз для данной сборки. `DewiarBuildID` в Info.plist
меняется при сборке; файл `state/screen-access-request.json` хранит только факт
попытки, а не решение macOS. После отказа повторный запуск той же сборки не создаёт
новый запрос. Переключатель «Запрашивать доступ к экрану при запуске новой сборки»
позволяет отключить автоматический запрос. Исходники и smoke-проверки системный
запрос не запускают.

macOS может не показывать Allow после ранее принятого решения. Тогда открывается
страница доступов Dewiar с точными шагами восстановления через системные настройки.
Во «Встречах» теперь есть собственные кнопки разрешения и перехода в настройки;
после возвращения из macOS статус обновляется и доступные окна загружаются.
Разрешение «Только запись системного звука» не считается разрешением экрана.

Эти изменения не заменяют постоянную подпись: сохранение разрешений между
разными ad-hoc сборками не гарантируется. Причина описана Apple в
[TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements).
Для постоянной идентичности требуется сертификат Apple Development / Developer ID
с приватным ключом; подготовка — в `macos-microphone-signing.md`.

Регрессии: `macos_screen_startup_test.py`, `macos_install_test.py`,
`mac_access_test.py`, `mac_access_ui_test.py`, `meeting_capture_access_ui_test.py`.

### Проверка установленной сборки

После финальной установки 3 ноября 2026 года подтверждены:

- новая страница восстановления автоматически открылась после системного отказа;
- при обновлении inode каталога приложения остался `20874321`;
- сохранена резервная ZIP-копия; установщик также удерживает `ui.lock`, не позволяя
  запустить интерфейс в момент замены содержимого;
- текущая запись Dewiar в macOS была включена, но не соответствовала новой ad-hoc
  сборке: реальный захват получал отказ;
- после удаления этой записи, добавления `/Applications/Dewiar.app` и системного
  `Quit & Reopen` команда установленного ядра `prompter_capture_apps` вернула 15 окон;
- `prompter_capture_test` вернула `ok: true`, `5120 × 2880`, источник `screen`,
  без сохранения тестового кадра.

Это подтверждает работу текущей установленной версии после восстановления доступа.
Сохранение разрешения при следующей ad-hoc пересборке не подтверждено и не гарантируется.
Постоянная подпись по-прежнему требует сертификата Apple с приватным ключом.

### Документы и файлы при запуске новой сборки (3 ноября)

После системного запроса экрана приложение последовательно проверяет чтение
рабочей папки и «Документов» из своего ядра. macOS при необходимости показывает
Allow. При отказе открываются раздел подготовки Dewiar и системные «Файлы и папки».
Проверка не читает содержимое файлов и не меняет рабочую папку.

Попытка фиксируется отдельно в `files-access-request.json` для текущего
`DewiarBuildID`. Повторный запуск этой же сборки не открывает настройки снова;
новая сборка проверяет доступ заново. Ошибка связи с ядром не считается успешной
проверкой и позволяет повторить попытку при следующем запуске. В режиме запуска
из исходников автоматического запроса нет. Переключатель
`ui.mac_files_request_at_startup` управляет этим поведением.

В «Безопасность → Доступы macOS» можно отдельно проверить Документы, Рабочий стол,
Загрузки, рабочую или выбранную папку и открыть настройки «Файлы и папки».
После изменения системного разрешения кнопка папки выполняет реальную проверку
повторно. Результаты чтения показываются как результаты последней проверки.

Нативный клиент ядра ждёт именно ответ `reply` своего запроса. События уровня
микрофона, состояния и чата между запросом и ответом игнорируются; общий тайм-аут
не продлевается этими событиями. Поэтому фоновое событие не превращает результат
проверки папки в пустой ответ.

### Кнопки встреч, календаря и заметок

Кнопки встречи и снимка используют общую проверку экрана: при отказе значки
блеклые, но доступны для нажатия и клавиатуры, чтобы запросить разрешение.
Запуск встречи и выбор снимка блокируются до действующего доступа. Уже принятое
решение macOS переводит пользователя в системные настройки вместо нового Allow.

Календарь и заметки требуют подтверждённого чтения «Документов» и рабочей папки.
Нажатие последовательно проверяет обе папки из установленного ядра; macOS может
показать Allow. При отказе открываются «Файлы и папки», целевой раздел не открывается.
После успешного разрешения открывается выбранный раздел. Одновременные нажатия
не создают дополнительные запросы. Возврат из настроек повторно проверяет доступ
к ранее запрошенным папкам; сохранённый результат не считается актуальным разрешением.
Бейджи календаря и заметок не перекрывают состояние отсутствующего доступа.

Проверки: `tests/hud_access_ui_test.py` (Chromium и WebKit), `tests/mac_access_test.py`.

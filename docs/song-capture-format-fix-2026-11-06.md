# Исправление ускоренной записи Core Audio

У записи «Дождь Жаров» обнаружился неверный WAV-заголовок. Процесс tap на macOS выбирает исходный формат приложения, например 48 кГц/стерео, но передаёт в stdout уже преобразованный поток 16 кГц/моно. Менеджер записи принимал событие `tap` за формат выходного PCM и сохранял WAV как 48 кГц/стерео. Поэтому 16‑кГц данные воспроизводились примерно втрое быстрее, а распознавание видело только короткую часть песни.

Теперь формат записи берётся из события `ready`, которое описывает фактический поток stdout. Событие `tap` используется только для диагностики исходного устройства. Добавлен регрессионный тест, запрещающий подменять 16 кГц/моно значениями 48 кГц/стерео.

Существующая запись была восстановлена без удаления исходного файла: PCM-полоса перенесена в новый WAV 16 кГц/моно. После этого полный разбор завершился на 33 фразах за 312,768 мс, с моделями GigaAM, Whisper large-v2 и Qwen3-ASR. Проверка ответа плеера через ffmpeg дала 312,8 секунды.

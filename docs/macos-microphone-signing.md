# Доступ к микрофону без повторных запросов

macOS хранит разрешение для идентичности подписанного приложения. В Dewiar перед обращением к микрофону проверяется системный статус; локальное значение «разрешено» не подменяет решение системы. Для обычного воспроизведения звука отдельный запрос доступа к динамикам не нужен; захват системного звука — другая функция.

Запрос микрофона теперь общий для всех окон и защищён блокировкой. Одновременные клики не открывают новые запросы. За один запуск допускается одна попытка системного запроса; после 60 секунд неопределённого ожидания кнопка освобождается, показывается переход в настройки и повторный запрос не создаётся. Существующие ответы «разрешено/запрещено» используются напрямую. Проверка статуса при открытии окна сама разрешения не запрашивает.

Во время ожидания HUD больше не пишет «Ядро занято (загружает модели)»: отображается ожидание разрешения macOS/подключения голосового ввода.

## Почему после пересборки разрешение может снова появиться

Текущие локальные сборки были подписаны ad hoc: их designated requirement привязан к хешу конкретной версии. Изменение программы меняет эту идентичность. Поэтому разрешение предыдущей сборки не гарантируется для следующей. Никакая запись `mic_allowed=true` в настройках не исправит идентичность приложения.

[Объяснение Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements), [правильная проверка разрешения](https://developer.apple.com/documentation/bundleresources/requesting-authorization-for-media-capture-on-macos).

Для сохранения разрешения между обновлениями нужна постоянная Apple Development или Developer ID Application подпись, неизменный bundle identifier `pro.dewiar.macos` и корректно подписанные обновления. На момент проверки `security find-identity -v -p codesigning` показал 0 доступных действительных сертификатов. Поэтому межверсионное сохранение разрешения пока не подтверждено и не заявляется как исправленное.

## Подготовка постоянной подписи

1. Пользователь входит своим Apple ID в Xcode → Settings → Accounts. Пароль не передаётся в чат.
2. Для выбранной команды в Manage Certificates создаётся Apple Development (если доступен для этой команды), либо импортируется имеющийся Developer ID Application с приватным ключом.
3. `security find-identity -v -p codesigning` должен показать действительную подпись.
4. Если подходящий сертификат ровно один, `packaging/macos.spec` выбирает его автоматически. Если несколько, необходимо явно задать `DEWIAR_CODESIGN_IDENTITY`; сборка не выбирает случайную команду.
5. Если предыдущая .app уже подписана постоянным сертификатом, сборка отказывается молча переходить на ad hoc, когда сертификат недоступен.
6. Первый переход с ad hoc на постоянную подпись потребует нового системного разрешения. После этого проверяются обычный перезапуск и два обновления с той же постоянной идентичностью.

Приложение не сбрасывает TCC, не редактирует базу разрешений, не создаёт поддельный designated requirement и не добавляет самодельный доверенный корневой сертификат.

Проверки без настоящего запроса микрофона: `macos_mic_permission_test.py` — все состояния, один запрос при параллельных вызовах, отсутствие нового запроса после тайм-аута, источник Python не получает разрешение вместо Dewiar, корректное отображение в интерфейсе. Системный Allow должен нажать пользователь.

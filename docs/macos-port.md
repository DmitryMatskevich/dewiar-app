# Mac-порт: состояние разработки

Основа: upstream `32fcd91`, Dewiar 0.45.3. Ветка: `macos-port`.

## Текущий результат

Работает текстовый прототип: существующий HUD и студия на Cocoa/WKWebView, ядро в отдельном процессе, локальный WebSocket с аутентификацией. Проверен запуск из исходников и собранной `.app`.

Это ещё не стабильная Mac-версия. Голос, LaunchAgent, интеграции, синхронизация личных данных и постоянная подпись не приняты.

## Запуск разработки

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-macos.txt
bash tools/run_macos.sh
```

Лаунчер использует отдельные данные в `work/mac-preview`, отключает синхронизацию и включает локальный режим. Для внешней модели потребуется осознанно настроить профиль и разрешить сетевые запросы. Перенос личной памяти и подключение основного аккаунта на этой стадии не выполнять.

## Проверки

```bash
.venv/bin/python -m pip install pytest playwright fastapi uvicorn python-multipart
.venv/bin/python -m playwright install chromium
.venv/bin/python tools/run_macos_checks.py
.venv/bin/python tools/smoke_macos.py
.venv/bin/python tools/macos_doctor.py
```

Наборы запускаются последовательно, с отдельными временными данными. Старые проверки, печатающие ❌ при коде выхода 0, считаются проваленными. Полные журналы сохраняются в `work/checks`.

## Сборка

```bash
.venv/bin/python -m pip install pyinstaller
.venv/bin/python -m PyInstaller --noconfirm packaging/macos.spec
.venv/bin/python tools/smoke_macos.py --bundle
```

Результат: `dist/Dewiar.app`, Apple Silicon. Runtime Python и библиотеки включены; при запуске ядра приложение вызывает собственный исполняемый файл с `--core`.

Без `DEWIAR_CODESIGN_IDENTITY` сборщик использует локальную ad-hoc подпись. Она не заменяет постоянный сертификат и нотариальное заверение. Действующих signing identities на компьютере при начале работ не обнаружено. Постоянство разрешений между сборками пока не проверено.

Двойной щелчок по `.app` запускает текстовый режим. Голос в собранном приложении пока отключён: отдельного переноса требуют рабочие процессы и вызовы `sys.executable`. При проверке из исходников используется обычный Python.

## Запуск без терминала

В исходниковом режиме больше не нужно каждый раз вручную выполнять `git pull`, смотреть
`git log` и запускать `tools/run_macos.sh`. После запуска Dewiar откройте меню приложения
`Dewiar → Обновить и перезапустить Dewiar` или студию → «Обновления» → «Обновить Dewiar и
перезапустить». Приложение само проверит текущую ветку, выполнит только
`git pull --ff-only`, покажет результат в окне агента и перезапустится после нового коммита.

Перед обновлением проверяется рабочая копия Git. При незакоммиченных файлах обновление
останавливается и ничего не меняет — сначала сохраните свою работу в коммите или уберите
её в отдельную ветку. Скрытый ввод пароля Git отключён, поэтому при проблеме доступа к
GitHub будет понятная ошибка, а не зависшее окно.

В установленной подписанной `.app` Git не запускается: для неё остаётся официальный
обновлятор в разделе «Обновления». Произвольный путь к shell-скрипту из интерфейса не
исполняется. Если пользователь явно просит выполнить команду или скрипт, агент может
использовать существующее подтверждаемое умение «Команды терминала»; опасные команды
отсекаются защитой и требуют отдельного подтверждения.

## Исправления первой очереди

- Проверки кода привязаны к содержимому рабочей копии и команде. Новая правка делает предыдущий результат неприменимым.
- Провал тестов после исчерпания повторов приводит к `failed`, а не к успешному завершению.
- Принудительное завершение не обходит проверку кода.
- Проекты без Git сравниваются с отпечатками исходной копии. Конфликты проверяются до переноса; пользовательские изменения в других файлах сохраняются.
- Удаление при принятии копии идёт через корзину. Перед переносом сохраняются исходные файлы в `_accept_backup` рядом с рабочей копией.
- Mac-пути настроек и состояния размещаются в Application Support, имя системы корректно передаётся модели.
- Учтены системные пути и ссылки `/private`; корзина использует API Finder.
- Выбор аудиоустройств Mac использует sounddevice.
- Серверный/текстовый режим не загружает слух и не запрашивает микрофон.
- Замеры памяти Mac используют psutil; резервные копии указывают `os: macos`.
- Корень рабочей папки канонизируется: дневник работает и при пути через `/var`.

## Дополнительная защита памяти

- Новые идентификаторы заметок рассчитываются по NFC; существующие ID сохраняются при другой Unicode-форме пути.
- Неоднозначные Unicode-имена и конфликты регистра в известном состоянии блокируют обмен.
- Обход источника с ошибкой папки не выдаётся за полный пустой список.
- Выгруженные файлы iCloud (`SF_DATALESS`) не читаются при составлении снимка и не считаются удалёнными.
- Ошибка чтения «Обо мне» останавливает синхронизацию.
- Не менее двух удалений, затрагивающих от 30% известного набора, либо 20 удалений одного вида останавливают обмен до отправки. Эти пороги консервативны; интерфейс подтверждения намеренного массового удаления ещё нужен.
- Курсор обмена не продвигается за записи, которые не удалось расшифровать или применить.
- Зеркало Obsidian нормализует ключи путей, проверяет читаемость файлов до изменений и останавливается при потере существенной части источников.
- Вложенная в CONFIG_DIR папка состояния не архивируется повторно как конфигурация: модели и ID синхронизации не попадают в слепок обходным путём.
- Закрытый слепок включает текущую сводку разговора, ленту чата и сырые дневные реплики; открытый экспорт их дополнительно не раскрывает.

Эти проверки проходят на локальных данных. Полная приёмка памяти ещё требует первого приёма на тестовом аккаунте, проверки импорта слепка и межплатформенной совместимости.

## Известные ограничения

- Нет завершённой атомарной транзакции принятия нескольких файлов; резервная копия сохранена, но автоматическое восстановление после аварии требует следующего этапа.
- Проверка тестов пока использует существующее определение команды и текстовый результат исполнения. Подтверждение числа выполненных тестов и профиль окружения проекта ещё нужны.
- Не все методы исходного оконного API перенесены с GTK. Проверены старт, базовые окна и связь с ядром; полный перечень оконных функций требует отдельной приёмки.
- Учёт памяти интерфейса и процессов WebKit на Mac неполный.
- ARM-сборка не проверена на Intel и других Mac.
- Авторизация подписок Codex/Claude Code пока описана в дорожной карте, но не реализована.

Названия моделей берутся из API сервера и не требуют ручной замены для macOS. Официальные инструкции: [Ollama macOS](https://docs.ollama.com/macos), [сервер LM Studio](https://lmstudio.ai/docs/developer/core/server).

В собранной .app подтверждены Ollama: установлена, API работает, 6 моделей; LM Studio: установлена, API работает, 3 модели. Пять тестов различают отсутствие программы, выключенный сервер и пустой каталог работающего сервера. Нативная проверка исходников и .app подтверждает статусы, корректные инструкции macOS и сохранение активного профиля. Прошли subscriptions_test и проверка подписи.

### Сервисы Dewiar отключены

В этой сборке `privacy.dewiar_services=false` по умолчанию. Ядро отклоняет HTTP-запросы и DNS-разрешение `dewiar.pro`, `dewiar.ru` и их поддоменов, независимо от `privacy.local_only`. Проверка срабатывает до выбора HTTP-прокси. Новости сервера не загружаются/не показываются; автоматические проверки обновлений, пульс и опрос ответов разработчика пропускаются. Раздел Dewiar.pro показывает сообщение об отключении, без предложения подключиться.

Это не общий запрет интернета: Ollama/LM Studio, официальные CLI Codex/Claude и загрузка моделей с других сайтов доступны по прежним правилам. Облачные модели/распознавание/синхронизация/общие боты Dewiar недоступны; собственные подключения к сторонним сервисам сохраняются. Локальная память и аккаунтные данные не удаляются. Вернуть сервисы можно явным `privacy.dewiar_services=true` в настройках; это не включает автоматически ранее выключенную синхронизацию или телеметрию.

Проверка: `tools/run_macos_checks.py dewiar_services_test.py security1019_test.py subscriptions_test.py macos_chat_test.py`; нативный smoke дополнительно проверяет, что объявление не открывается, а раздел сервиса отображается отключённым.

### Отдельные беседы, поиск и архив

В «Чате» появились список бесед, «Новый чат», поиск внутри выбранной беседы, «В архив», «Восстановить» и «Удалить чат» с подтверждением. Действия относятся ко всей беседе со всеми вопросами и ответами. Прежняя общая лента автоматически представлена одной беседой `legacy`; данные не удаляются. Новые записи получают `chat_id`, выбор сохраняется в `state/chat-current.json`. История больше не обрезается автоматически по прежнему пределу 5000 реплик.

У бесед отдельные файлы модельного контекста (`chat-contexts/`, у прежней беседы — `conversation.json`). Переключение сохраняет прежний контекст и восстанавливает выбранный; если сохранённого контекста нет, используются последние текстовые сообщения этой беседы. Начало запроса и смена беседы упорядочены; переключение/архивирование во время ответа или сворачивания контекста отклоняется с понятной ошибкой. Фоновое сворачивание захватывает свою беседу и не может записать её содержание в новый выбранный контекст. Общие заметки, дневник и память о пользователе остаются общими.

Архивы лежат отдельными gzip-файлами в `state/chat-archive/`, содержат все сообщения и сохранённый контекст. Они не загружаются в ChatLog.items при запуске, не участвуют в автоматическом поиске модели по основной ленте; читаются при открытии архива. Архив занимает место на диске, обычно существенно меньше исходного текста, и временно использует память при просмотре. Вложения остаются во «Входящих», архивирование и удаление чата их не удаляет. Сжатие не является шифрованием. Закрытая резервная копия с паролем включает архивы, отдельные контексты и выбранную беседу; открытая копия их не содержит.

Перед удалением основной истории архив полностью записывается; перед удалением архивного файла при восстановлении полностью записывается основная история. Ошибка записи сохраняет исходные данные. При сбое между двумя файлами может остаться дополнительная восстановительная копия, но дубли активных сообщений скрываются в архиве.

Проверки: `chat_archive_test.py`, `macos_chat_test.py` (также `--bundle`), `studio_chat_test.py`, `macos_backup_test.py`; нативный Cocoa/WebKit smoke — `chat_search_archive=true`. Платные модели и пользовательская переписка в проверках не используются.

### Автовыбор моделей, расписание и лимиты — 27.10.2026

В начале «Модели» показана таблица всех профилей: модель, приоритет 1–9 (1 — первый), часы работы, доступность, баланс/лимиты и переход к настройке. `llm.auto_select` включает автоматический выбор. Профиль имеет `priority`, `routing_enabled`, `schedule_enabled`, `schedule_start`, `schedule_end` и `timeout` (5–1800 секунд). По умолчанию профиль доступен круглосуточно; часы ежедневные, в часовом поясе Mac. Конец 24:00 поддерживается, например 20:00–24:00. Ночные интервалы 22:00–06:00 поддерживаются. Начало включительно, конец исключительно; одинаковые границы означают сутки. Расписание проверяется перед новым запросом, начатый ответ в полночь не прерывается. При равных приоритетах предпочтение ручному llm.active, затем стабильный порядок ID. При ручном режиме работает выбранный профиль без автоматического перехода.

При исчерпанном лимите, ошибке подключения, тайм-ауте или пустом ответе до первого выданного события пробуется следующая допустимая модель. Каждая модель в цепочке пробуется один раз (её прежние адаптации несовместимого формата внутри транспорта сохраняются). После начала текста или выдачи вызова инструмента цепочка не переигрывается. Неуспешная модель временно исключается: 60 секунд при обычной ошибке, 5 минут при ошибке лимита без известного сброса, либо до переданного сервисом времени сброса. «Обновить лимиты и доступность» разрешает явную повторную попытку. При отсутствии доступных моделей показывается ошибка; запрещённые серверы Dewiar и внешние модели в local_only не включаются в цепочку.

Codex: официальный `account/rateLimits/read`, без генерации и независимо от неустойчивого `account/read`/workspace discovery. Показываются переданные окна лимитов, процент остатка, время сброса и дополнительные кредиты (это отдельная величина, ноль дополнительных кредитов не означает исчерпание подписки). Источник: [официальный протокол Codex app-server](https://learn.chatgpt.com/docs/app-server). Настоящий запрос подтвердил 82% остатка недельного окна на момент проверки; значения всегда снабжены временем снимка.

Claude Code: наблюдаются `rate_limit_event`, `rate_limit_info`, utilization и переданные unifiedWindows при обычных пользовательских запросах. Эти данные не вычисляются из стоимости запроса. Бесплатного документированного запроса полного остатка через используемый CLI не найдено: до события выводится «нет данных», отдельная платная генерация ради проверки лимитов не отправляется. Поля события проверены по [первичному примеру в репозитории Anthropic](https://github.com/anthropics/claude-code/issues/91857). Сервис может сообщить только статус без процента. Лимиты подписок обозначены как общие для аккаунта/группы; неподтверждённое соответствие конкретной модели не выдумывается.

Для обычных API собираются переданные сервером HTTP-заголовки остатка токенов/запросов. Для OpenRouter используется [официальный read-only /api/v1/key](https://openrouter.ai/docs/api_reference/limits): бюджет и лимит средств ключа в USD, не приравниваемые к общему балансу аккаунта. Произвольные endpoint для баланса не опрашиваются, ключи не пересылаются на другие хосты. Если информации нет, это явно показано. Снимки лимитов хранятся без токенов авторизации в state/model-quotas.json с правами 600; показывается время обновления. Нулевой неизвестный остаток не подставляется.

Проверки: model_router_test.py (12), subscriptions_test.py (включая чтение квоты без account/read/генерации), security1019_test.py, voice_mode_test.py, dewiar_services_test.py. macos_chat_test.py с настоящим ядром/локальными серверами проверяет 429 и полное молчание с переходом на резервную модель, также --bundle. Нативный smoke проверяет настройки приоритета/24:00, откат неудачного сохранения, показ нулевой и неизвестной квоты: model_routing_controls=true.

Несколько моделей одной подписки сохраняются отдельными профилями. Повторный выбор той же модели обновляет её профиль и сохраняет приоритет/расписание. Лимиты обновляются при открытии раздела, по кнопке и примерно раз в минуту, пока «Модели» видны; перечитывание локальных снимков — каждые 15 секунд. Для Claude это перечитывание событий CLI, без генерации ради мониторинга. Общий deadline запроса передаётся в CLI, а повторные адаптации HTTP учитывают оставшееся время ожидания.

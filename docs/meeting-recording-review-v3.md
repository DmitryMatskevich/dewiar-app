# Запись встреч: интеграция экспертных исправлений и проверка на Mac

Дата: 30.10.2026. Продолжение [первого описания](meeting-recording-review.md), [разбора v2](meeting-recording-review-v2.md) и [сравнения AudioTranscripts](audiotranscripts-comparison.md).

## Что было принято

Эксперт верно указал на потерю микрофона при системной записи, обрезание длинного разговора, ложный успех тихой дорожки, общие поля старой/новой встречи и блокирующую обработку после stop. К моменту этой интеграции изменения v2 и Swift-исходник уже находились в незакоммиченной рабочей папке. Они проверены и дополнены; наличие файла не считалось подтверждением работоспособности.

Репозиторий [raliev/audiotranscripts](https://github.com/raliev/audiotranscripts) теперь перенаправляется на [raliev/ushi](https://github.com/raliev/ushi). При этой доработке использованы архитектурные идеи и существующие локальные изменения; дословный перенос исходников внешнего проекта не выполнялся. Вопрос лицензии требуется решать отдельно перед любым заимствованием кода.

## Изменения

| Область | Реализация |
|---|---|
| Две дорожки | Системный звук и микрофон сохраняются отдельно плюс общий WAV. `record_me` управляется в настройках. Отложенная расшифровка подписывает по источнику; эхо фильтруется эвристикой |
| Нативный звук Mac | `native/macos/dewiar_audio_tap.swift` собран для arm64. Список приложений не запускает запись. `--self-test` проверяет stereo AudioBufferList → mono 16 kHz на синтетическом сигнале |
| Выбор источника | Настройки «Встречи»: Автоматически / Core Audio / BlackHole и выбор приложения. Явный Core Audio при недоступности сообщает ошибку, а не подменяется другим способом |
| Разрешения | В `.app` и helper plist есть `NSAudioCaptureUsageDescription`. Удалён вызов частного API смены ответственного процесса; атрибуция доступа остаётся за macOS |
| Следование выходу | Tap отслеживает обычный выход приложений, а не отдельный выход системных уведомлений. Его выдача использует monotonic uptime вместо изменяемого настенного времени |
| Управление процессом | Helper запускается отдельной process group; чтение PCM ограничено ожиданием, при остановке завершается группа. Тест проверяет зависший stdout |
| BlackHole stereo | Читаются два канала и сводятся в mono. Сигнал только справа не теряется. Capture считает overflow/drop событий |
| Последние фразы | `_Segmenter.flush()` передаёт речь без завершающей паузы. STT ждёт завершения producer, а не только пустой очереди |
| Остановка | Stop выставляет состояние и возвращает управление; закрытие устройств, ожидание потоков, видео и итог выполняются фоном. Новая встреча не начинается поверх обработки предыдущей |
| Длинная встреча | Итог по частям с таймкодами; OCR — справочник терминов; сырые реплики сохраняются в `.lines.json` |
| Кадры и диск | Устойчивая сцена и возврат к слайду дедуплицируются. Для видео с аудио больше не сохраняется неиспользуемая папка JPEG каждого такта |
| OCR | Для автоматических кадров — отдельная ограниченная очередь; захват не ждёт распознавания. Ручной снимок сохраняет синхронный ответ с OCR. Перед итогом ожидаются принятые задания OCR |
| Расписание | Восстановление зависших статусов, пропущенные встречи, version=1 для файла расписания с чтением прежнего массива |
| UI | Два подписанных индикатора уровня, диагностика пропусков/ошибки микрофона, этапы «сохранение → расшифровка → часть N из M → итог». Новые поля имеют title и клавиатурный доступ |
| Help | Описаны способы захвата, приложение, отдельный микрофон, тишина, обработка после stop и формат файлов. Уточнено, что удалённый STT получает звук, а внешний LLM — текст |
| Git | `native/macos/bin/` исключён как результат сборки. Исходник Swift, plist и build script должны храниться в Git при отдельном запросе коммита |

## Где проверять код

- `core/audio_io.py`: `Capture`, `TapCapture`, `LoopbackCapture`, `list_audio_apps`.
- `core/prompter.py`: `start`, `stop`, `_after_stop`, `_finish_capture`, `_them_loop`, `_stt_loop`, `_Segmenter.flush`, `_post_transcribe`, `_summary_text`, `_ocr_loop`.
- `core/engine_commands.py`: `prompter_audio_apps`, `prompter_start`.
- `ui/settings.html`, `ui/studio/prompter.js`: способы записи и выбор приложения.
- `ui/prompter.html`: уровни, ошибки и прогресс итога.
- `native/macos/dewiar_audio_tap.swift`, `tools/build_audio_tap.sh`, `packaging/macos.spec`: нативная сборка и включение helper в будущую `.app`.

## Проверки

Выполнены сборка Swift, `--list` и `--self-test` на текущем Mac. Последний тест не использует реальные аудиоустройства и не требует TCC. Код скомпилирован с установленным SDK; это не доказывает качество захвата реального звонка.

Регрессионные наборы:

```sh
bash tools/build_audio_tap.sh
.venv/bin/python tests/meeting_capture_regression_test.py
.venv/bin/python tests/meeting_audio_settings_test.py
.venv/bin/python tests/prompter_dual_track_test.py
.venv/bin/python tests/prompter_recording_test.py
.venv/bin/python tests/prompter_capture_test.py
.venv/bin/python tests/prompter_links_test.py
.venv/bin/python tests/prompter_schedule_test.py
.venv/bin/python tests/meeting_video_test.py
.venv/bin/python tests/meeting_video_ui_test.py
.venv/bin/python tests/prompter_end_test.py
.venv/bin/python tests/context_help_test.py
```

Новый regression test проверяет последний незавершённый сегмент, stop при заблокированном close устройства, дочитывание хвоста producer, правый stereo-канал, старое/новое расписание, ограниченное ожидание helper и OCR, который не тормозит кадры. Тесты UI используют подменённое ядро. Тест кадра изолирован от звуковых устройств; настоящий звонок через него не запускается.

Перечисленные наборы прошли на текущем Mac. Настройки дополнительно проверены на сохранение выбранного приложения после обновления списка и экранирование названий. Контекстная справка: 34 статьи, title у 430 кнопок, отсутствие вызовов модели при чтении, поиск и клавиатурная навигация. Синтаксические проверки Python/JavaScript и `git diff --check` пройдены.

## Что ещё нельзя считать принятым

1. Реальный звонок в подписанной `.app`, запрос/отказ TCC, смена наушников и сон Mac требуют ручной приёмки. Установленная пользовательская `.app` этой итерацией не заменялась. Helper собран ad-hoc; стабильность разрешений после обновлений требует постоянной подписи.
2. Process Tap пока снимает только звук приложений. Микрофон остаётся отдельным Python/PortAudio-потоком с выравниванием кадров. Это не единое агрегатное устройство с микрофоном и не доказанная sample-accurate синхронизация.
3. Настоящая видеозапись через ScreenCaptureKit/SCRecordingOutput не реализована: остаётся видео по кадрам с аудио. Это следующий отдельный этап с интерфейсом start/pause/stop и тестами синхронизации.
4. Для all-target исключается PID ядра. Голос, воспроизводимый отдельным процессом TTS/плеера, может потребовать отдельного исключения; не обещать полное подавление всех звуков Dewiar до проверки.
5. Разные собеседники на одной системной дорожке не распознаются персонально по голосам. Метка «Собеседник» означает источник; извлечение имён из текста не является диаризацией.
6. Текстовый фильтр эха — эвристика. Совпадающий повтор собственной реплики может быть отфильтрован; исходные WAV остаются для проверки.
7. Сборка заметок по частям зависит от лимита контекста и ответа LLM. Для очень длинных многодневных записей и неответивших частей нужна дальнейшая иерархическая свёртка и повтор обработки.
8. В памяти ограничено до 20 000 строк; TXT и WAV сохраняются на диск. Для встреч сверх этого размера необходимо строить итог из дискового журнала, а не обещать неограниченную память.
9. Скорость разных STT и качество на тишине нужно измерять на одном наборе аудио. Абсолютное утверждение «GigaAM в 20 раз быстрее и не галлюцинирует» не является результатом этого прогона.

## Ручная проверка после запуска новой версии из исходников/сборки

1. В «Встречи → Способ записи» выбрать Core Audio; обновить список, выбрать приложение звонка.
2. Включить запись и «Записывать и мой микрофон». Предупредить участников. Выдать системные разрешения записи звука и микрофона.
3. Поочерёдно произнести разные тестовые фразы с обеих сторон; убедиться, что двигаются соответствующие индикаторы.
4. Проверить паузу звука, смену выхода и остановку; окно сразу показывает сохранение, затем обработку.
5. Прослушать `Вы.wav`, `Собеседник.wav`, общий WAV; проверить подписи и временные метки TXT.
6. Для презентации проверить возврат к слайду, OCR и MP4. Убедиться, что лишняя папка покадровых JPEG не растёт при записи с аудио.
7. Проверить поведение без разрешения, без helper и с явно выбранным BlackHole. Пустая дорожка должна быть обозначена в протоколе.

Незакоммиченные изменения других функций сохранены. Автоматического коммита, push и публикации новой `.app` не выполнялось.

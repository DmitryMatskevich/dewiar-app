# Локальный модуль песен

Работает отдельным процессом Python 3.12. Основной `.venv`, настройки LLM/STT/TTS и каталоги существующих голосов не изменяются. Для вывода интерфейса runtime не нужен; для полной обработки нужны заранее установленные веса.

## Установка на этом Mac

В отдельном окружении установить `requirements-songs.txt`. Рабочий путь:

`~/Library/Application Support/Dewiar/runtimes/songs/bin/python`

Явный установщик весов: `tools/install_song_models.py`. Он сохраняет ревизии и пути в `work/song-verification/model-install.json`; для установленной `.app` манифест копируется в `~/Library/Application Support/Dewiar/runtimes/songs-models.json`.

Установлены Whisper large-v2 MLX, Qwen3-ASR 0.6B и Qwen3 ForcedAligner 0.6B. GigaAM использует существующие файлы Dewiar. Worker работает с offline-флагами и запретом записи bytecode в подписанную `.app`. Установка весов не является частью открытия вкладки/распознавания.

Для Chordino выполнить `tools/install_song_chordino.py` Python 3.12 после установки инструментов clang++, cmake, Homebrew boost и libsndfile. Это отдельный явный шаг. Скрипт проверяет закреплённые Git revisions, собирает CLI и сохраняет исходники с лицензиями в `runtimes/chordino/sources`. Исполняемый файл — `runtimes/chordino/bin/chordextract`, манифест содержит SHA256. Применяется встроенный словарь Chordino; произвольный системный chord.dict не подхватывается.

Источники:
- [Qwen3-ASR и выравниватель](https://github.com/QwenLM/Qwen3-ASR).
- [Whisper MLX](https://github.com/ml-explore/mlx-examples/tree/main/whisper).
- [Chordino / NNLS Chroma](https://github.com/c4dm/nnls-chroma), GPL-2.0-or-later, revision `4c5f214a75cb354f8d8c933e161377c5b4d83713`.
- [Vamp SDK](https://github.com/vamp-plugins/vamp-plugin-sdk), revision `44c2487763eb248a933e9eff9169cfadee375009`.

Chordino выбран как дополнительный готовый алгоритм с NNLS-признаками и басом. Чужие оценки качества не переносятся на пользовательский набор. Он также ошибается на пении и старых записях; результат остаётся предварительным. Без бинарника либо при его ошибке используется CQT/Viterbi, причина резерва сохраняется в результате.

HTDemucs проверялся отдельно в `.songs-separation-venv` с совместимыми torch/torchaudio. Это эксперимент сравнения, а не автоматический новый вход для каждого распознавателя. Не понижать torch основного музыкального окружения ради torchaudio.

## Проверки

Из каталога `app`: `.venv/bin/python tools/test_songs_safe.py --report work/song-verification/tests-final.json`.

UI без моделей/настроек: `.venv/bin/python tools/songs_ui_preview.py`. Он создаёт временное хранилище и маркирует тестовые данные.

После установки: проверить список, открыть карточку, выполнить реальный разбор, прослушать, сверить настройки и `codesign --verify --deep --strict /Applications/Dewiar.app`. Проверка только исходников не заменяет проверку установленного приложения.

## Итоговый лист и воспроизведение

В «Задачи → Песни» аккорды выводятся над текстом моноширинным шрифтом, с транспозицией на полтона, копированием чистого текста, до трёх ссылок на источники и проигрыванием сохранённой записи. Пауза сохраняет позицию; остановка сбрасывает её. Транспозиция меняет обозначения аккордов, а не звук записи.

Во время прослушивания подсвечивается текущее слово, при переходе к следующей строке она прокручивается к середине экрана. Пауза и остановка сохраняют выделенное слово; после остановки новый запуск начинается с начала записи. Валидные сохранённые времена слов используются непосредственно. Для слов без меток (включая текст с устаревшим выравниванием после ручной правки) время приблизительно распределяется внутри фразы между известными опорными словами. Такое выделение помечается в листе и подсказке слова как приблизительное; оно не считается новым результатом выравнивателя.

Итоговые строки ограничены 42 символами и дополнительно адаптируются к ширине окна. Разбиение сохраняет порядок всех слов и привязки; длинное неразделимое слово переносится средствами CSS. Аккорды занимают только одну строку над текстом. Среди пересекающихся обозначений выбирается совместимый набор с максимальной суммарной длительностью звучания: так короткие колебания анализа уступают доминирующему аккорду. Непересекающиеся смены остаются. Выбор пересчитывается после транспозиции и изменения ширины, используется также при копировании и экспорте. Полный набор кандидатов остаётся в редакторе фраз; карточки, пользовательские правки и исходные события не перезаписываются.

Перенос строки или начало следующей фразы не повторяет уже звучащий аккорд. Исходные события, времена, ручные привязки и текст сохраняются. Возврат к аккорду после другого аккорда или тишины остаётся видимым. Это же представление используется для копирования и ChordPro.

Дополнительные проверки интерфейса: `node tests/song_sheet_js_test.cjs` и `node tests/song_playback_js_test.cjs`.

Проверка всей сохранённой библиотеки: `.venv/bin/python -B tools/audit_song_layout.py --report work/song-verification/layout-audit.json`. Она сверяет порядок всех слов, сохранность реальных событий аккордов, границы привязок, отсутствие добавленных повторов и неизменность исходных карточек. Модели и сеть не используются. Длинные строки переразбиваются без одно-двухсловных хвостов, вызванных лимитом ширины; явные переносы и самостоятельные короткие ответы сохраняются. Ошибки самого распознавания этот аудит не исправляет и не объявляет проверенным текстом.

Кнопки «Предыдущая строка» и «Следующая строка» перематывают полную запись к началу соседней отображаемой строки и прокручивают к ней лист. Во время паузы переход сохраняет паузу. Вступление ведёт к первой строке; за первой/последней строкой переход отключён. При подготовке записи и прослушивании отдельного фрагмента кнопки недоступны. Отдельная кнопка сброса тональности удалена; сдвиг меняется стрелками на полтона.

В списке песен действия представлены иконками: проиграть/пауза, стоп (также отмена подготовки), редактировать и удалить с подтверждением. Список и редактор используют один плеер; запуск другой песни завершает прежнее прослушивание. Запуск из списка не прокручивает экран к редактору, а открытие уже звучащей карточки сохраняет воспроизведение.

Аккорды в паузе перед фразой входят в общий выбор обозначений над её первой отображаемой строкой. Несколько соседних блоков проигрыша не создают отдельные строки аккордов друг под другом; окончание без текста также сводится к одной строке. При тесной раскладке остаются доминирующие по длительности события. Это только итоговое представление: все исходные смены и их времена сохраняются в редакторе. Лист, копирование и ChordPro используют одну функцию `presentationLines`. Ширина рассчитывается по явным свойствам обычного и жирного моноширинного шрифта, поскольку сокращённое CSS-свойство `font` в браузере может оказаться пустым.

Регрессия границ «пауза → текст»: `.venv/bin/python -B tests/song_sheet_layout_ui_test.py`. Для проверки всей библиотеки можно передать `--library <public-song-snapshot.json> --report <report.json>`: стенд читает только подготовленную копию, использует настоящий интерфейс и проверяет отсутствие соседних строк аккордов, выходов за край, потерь слов и различий с копированием на ширинах 375/800/1440 px. Параметр `--assets` позволяет проверить файлы из установленной сборки.

Каждая строка текста и её аккорды находятся в общем блоке `.song-paper-line`: между ними нет отступа, разделителя строфы или разрыва при печати. Пустые строки допустимы только между такими блоками. Браузерный аудит проверяет также общий контейнер и соприкосновение границ строки аккордов и текста, с подключёнными стилями темы студии; доступны `--theme light` и `--theme dark`.

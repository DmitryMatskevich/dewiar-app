# Контакты macOS и Dewiar

Раздел «Контакты» находится в левом меню настроек. Используется официальный Contacts.framework через PyObjC. Системное разрешение и варианты полного/ограниченного доступа описаны в [документации Apple](https://developer.apple.com/documentation/Contacts/accessing-the-contact-store). Наличие файла адресной книги на диске не заменяет системного разрешения.

## Первое подключение и импорт

1. Откройте Dewiar.app → «Контакты» → «Разрешить доступ к Контактам».
2. Ответьте в системном окне macOS. Если доступ запрещён, кнопка «Настройки macOS» открывает нужный раздел; затем нажмите «Проверить доступ».
3. Нажмите «Прочитать доступные контакты». Это предварительный просмотр, ещё без сохранения в Dewiar.
4. Выберите все доступные карточки или отдельные. Фильтр не снимает ранее сделанные отметки; число выбранных видно перед импортом.
5. Подтвердите импорт. По умолчанию прежние локальные копии сохраняются; для обновления включите соответствующий флажок.

При ограниченном системном доступе «все» означает только разрешённый macOS набор. Список ограничен 20 000 карточек: превышение завершает чтение явной ошибкой, а не незаметным усечением. Перед импортом проверяются срок/токен предварительного просмотра и доступность выбранных идентификаторов. Изменившийся доступ/источник требует нового чтения списка.

Копируются имя, фамилия, отчество, организация, телефоны, почта и дата рождения. Не читаются заметки Contacts, фотографии и почтовые адреса. Импорт не пишет в системную книгу и не создаёт напоминания о днях рождения. Отсутствующие карточки не удаляются из Dewiar. При повторном импорте учитываются идентификаторы источника; совпадение только ФИО не объединяет разных людей. Локальная ручная копия с совпавшими основными полями может быть повторно использована; две системные карточки с разными идентификаторами не объединяются только по прочитанным основным полям.

## Упоминание ФИО

В собственных локальных сообщениях и голосовом вводе агент предлагает карточку. Основной вопрос продолжает обычную обработку. Поиск системного совпадения выполняется в фоне, чтобы чтение адресной книги не задерживало основной ответ; ошибки/тайм-аут не означают, что человека в книге нет.

- Найдено в macOS — просмотрите данные и выберите конкретную карточку для копирования.
- Несколько совпадений — выбор обязателен, первый результат автоматически не сохраняется.
- Есть в Dewiar — можно открыть существующую карточку.
- Совпадения нет/доступ ещё не разрешён — доступна форма новой карточки. Отсутствие доступа не считается доказанным отсутствием человека.

После отдельного ФИО или команды про контакт короткий ответ задаёт вопрос без обращения к LLM. «Да» относится к такому вопросу только в той же беседе в течение пяти минут; открывает проверку карточки, но не сохраняет её. Явное «создай контакт»/«скопируй контакт» также открывает интерфейс проверки. После иной темы короткое «да» не принимается за согласие на контакт. Ненужное предложение можно отключить для этого человека в текущей беседе или отключить функцию в целом.

Распознавание локальное и ограниченное: полное русское ФИО с отчеством, ряд сочетаний имени и фамилии, явная фраза про контакт и уже известные имена. Это не универсальный NER для всех языков/падежей. Автоматическое извлечение из вложений, картинок, модельных ответов, сообщений внешних отправителей и фоновых задач не выполняется.

## Создание и удаление

По выбору пользователя новое создание по умолчанию включено **в обоих приложениях**. Укажите поля → «Проверить и создать» → проверьте данные и место сохранения → подтвердите. Запись в macOS может далее синхронизироваться через её учётные записи; это зависит от настроек системных Контактов. Для явного сохранения только в Dewiar снимите флажок системной копии. При отсутствии разрешения приложение не переключается на локальное сохранение молча.

Повтор той же операции не создаёт второй контакт. При неподтверждённом исходе системного сохранения автоматический повтор блокируется: проверьте Контакты macOS и импортируйте найденное. Если журнал не удалось сохранить до системного вызова, системная книга не меняется. Если системная запись прошла, а локальное сохранение не подтвердилось, требуется проверка результата.

Удаление кнопкой «Удалить копию из Dewiar» затрагивает только локальную копию. Изменение и удаление существующих системных карточек не реализованы. На первом этапе локальное редактирование выполняется через обновление при импорте либо создание другой карточки; отдельного редактора существующей копии нет.

## Хранение и разрешения

- Локальный файл: `STATE_DIR/contacts.json`, права 0600, атомарная замена. Это приватный JSON, а не обещание шифрования данных на диске.
- Контакты не добавляются автоматически в контекст модели, Obsidian или синхронизацию Dewiar. Системная адресная книга имеет собственные правила синхронизации.
- Закрытый слепок с паролем включает контакты, открытый ZIP — нет. После восстановления файл имеет права 0600; обычный механизм восстановления перезапускает ядро.
- Запрос доступа только по явной кнопке, один нативный запрос за запуск; ожидание ограничено 60 секундами. Проверки статуса не запрашивают доступ. Постоянная подпись нужна для стабильной идентичности приложения между обновлениями.
- Установлены `pyobjc-framework-Contacts==12.2.2`, `NSContactsUsageDescription`. Право чтения заметок Contacts не запрашивается.

## Проверки и границы

`contacts_test.py`: импорт выбранных и 1000 карточек, повторы, однофамильцы, обновление/сохранение прежних копий, ограничение/отзыв доступа, устаревший список, приватные права файла, дедупликация создания, неопределённый исход и ошибки диска, Unicode, черновик и порядок ФИО, подтверждение, фоновые совпадения и подавление подсказок, родные bindings карточки без сохранения, закрытый/открытый слепок.

`contacts_flow_test.py`: настоящее ядро с недоступной моделью, предложение ФИО, голосовое «да» без записи, черновик, требование подтверждения, локальное создание/просмотр/удаление, повтор и сохранение исходного вопроса. В экзаменационном режиме нативное чтение отключено, запись системных контактов запрещена.

Cocoa/WebKit smoke использует синтетические карточки и проверяет частичный/полный импорт, повтор, ограниченный доступ, создание по умолчанию в двух местах, отказ от подтверждения, результат и отсутствие системного запроса при открытии страницы. Отдельно настоящий бинарник читает статус разрешения без запроса. Пользовательская адресная книга в этих проверках не читается и не изменяется. Проверка импорта/записи в настоящую системную книгу требует системного разрешения пользователя и выбранной им тестовой карточки.
